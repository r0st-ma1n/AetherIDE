# Контракт плагина и адаптера формата

Общий для всех форматов (VST3, CLAP, AU) и для headless-хоста договор между плагином
(наследник `aether::PluginProcessor`) и адаптером, который связывает его с хостом.
Адаптер знает только этот контракт — класс плагина ему неизвестен.

Если адаптеру нужно что-то сверх этого документа, сначала меняется контракт (здесь и в
`framework/core`), потом адаптер.

## Из чего состоит плагин

| Что                     | Где                                | Кто предоставляет                                 |
| ----------------------- | ---------------------------------- | ------------------------------------------------- |
| Описание (`PluginInfo`) | `aether/PluginInfo.h`              | `static PluginInfo pluginInfo()` в классе плагина |
| Точка входа             | `aether/PluginFactory.h`           | `AETHER_PLUGIN(ClassName)` в одном `.cpp`         |
| Процессор               | `aether/PluginProcessor.h`         | наследник `PluginProcessor`                       |
| Параметры               | `aether/AudioProcessorParameter.h` | добавляются в конструкторе процессора             |
| Состояние               | `aether/PluginState.h`             | `getState()` / `setState()` базового класса       |

Один плагин на бинарник. Без `AETHER_PLUGIN` бинарник не слинкуется, с двумя — тоже.

## Что делает адаптер

1. **Описание.** `aether::pluginFactory().info()` — до создания экземпляра. Адаптер
   вызывает `validatePluginInfo()` и выводит из `PluginInfo::id` идентификаторы своего
   формата (VST3 FUID, CLAP id, коды AU) детерминированно: один `id` — всегда одни и те же
   идентификаторы.
2. **Создание.** `pluginFactory().create()` — новый экземпляр, ещё не подготовленный.
   Параметры уже созданы: адаптер регистрирует их у хоста по `parameters()` —
   `numericId()`, имя, единица, `stepCount()`, флаги, `defaultValue()` в нормализованном
   виде, текст через `valueToText()` / `textToValue()`.
3. **Шины.** Адаптер спрашивает `isBusLayoutSupported()` и отказывает хосту в остальных
   раскладках. В v1 плагины поддерживают mono→mono и stereo→stereo, sidechain нет.
4. **Подготовка.** `prepare(ProcessSetup)` при активации и при каждом изменении sample
   rate, максимального размера блока или раскладки. Повторный `prepare()` сам вызывает
   `release()`.
5. **Обработка.** На каждый блок адаптер:
   - применяет изменения параметров от хоста: `setNormalizedValue()` (в v1 — последнее
     значение в блоке; сглаживание делает плагин через `SmoothedValue`);
   - собирает `ProcessContext` из указателей хоста без копирования (`AudioBuffer` — view);
   - вызывает `process()`.
6. **Остановка.** `release()` при деактивации; затем экземпляр можно снова подготовить
   или удалить.
7. **Состояние.** `getState()` при сохранении проекта или пресета, `setState()` при
   загрузке. Байты непрозрачны для адаптера и хранятся как есть.
8. **Задержка и хвост.** `getLatencySamples()` и `getTailSeconds()` сообщаются хосту
   после `prepare()`.

## Потоки

| Вызов                                                                                         | Поток                                       |
| --------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `pluginFactory().info()`, `create()`, деструктор                                              | main                                        |
| `prepare()`, `release()`, `isBusLayoutSupported()`, `getLatencySamples()`, `getTailSeconds()` | main                                        |
| `process()`                                                                                   | audio                                       |
| `getState()`, `setState()`                                                                    | main, могут идти одновременно с `process()` |
| `valueToText()`, `textToValue()`                                                              | main / UI                                   |
| `AudioProcessorParameter::value()`, `setValue()`, `setNormalizedValue()`                      | любой, lock-free                            |

`prepare()` и `release()` никогда не вызываются одновременно с `process()`: адаптер
останавливает обработку на время подготовки.

Значения параметров атомарны, поэтому `setState()` во время обработки безопасен для них.
Пользовательские данные из `loadCustomState()`, которые читает `processBlock()`, плагин
синхронизирует сам — без блокировок в аудиопотоке.

## Что запрещено в аудиопотоке

В `process()` / `processBlock()` и во всём, что они вызывают:

- выделять и освобождать память (`new`, `std::vector::push_back`, `std::string`, …);
- брать мьютексы, ждать, спать;
- файловый и сетевой ввод-вывод, логирование в консоль;
- бросать исключения: `process()` — `noexcept`, исключение завершит хост;
- вызывать `valueToText()` / `textToValue()`, `getState()` / `setState()`, `prepare()`.

Что можно: читать и писать значения параметров, `SmoothedValue`, работа с буферами из
`ProcessContext`. Тест на «не аллоцирует» — `AllocationCounter` из
`framework/core/tests/support/` (см. [testing.md](../standards/testing.md)).

## Гарантии для плагина

- `processBlock()` вызывается только между `prepare()` и `release()`.
- В блоке `output.numSamples() <= ProcessSetup::maxBlockSize`; блок может быть пустым.
- У `input` и `output` одинаковое число сэмплов, число каналов совпадает с
  `ProcessSetup::layout`.
- `input` и `output` могут указывать на одну память (in-place): читать входной сэмпл
  нужно до записи выходного с тем же индексом.
- Если у плагина есть bypass-параметр (`addBypassParameter()`) и он включён, `process()`
  копирует вход в выход и не вызывает `processBlock()`. Для плагинов с ненулевой
  задержкой bypass без задержки сдвинет звук — в v1 таких плагинов нет.

## Неизменяемые идентификаторы

После релиза плагина нельзя менять:

- `PluginInfo::id` — по нему DAW находит плагин в проектах;
- строковые id параметров — по ним (через `numericId()`) хранятся значения и автоматизация.
