# Сборка из IDE

Кнопка **Build** в панели Build собирает открытый проект (`ide/electron/main/buildRunner.cjs`)
в `<проект>/build`. Конфигурация — **Release** или **Debug** в выпадающем списке рядом с
кнопкой; выбор запоминается.

## Что происходит

1. **Проверка инструментов** (`toolchain.cjs`):
   - CMake 3.22+ в `PATH`;
   - Windows: Visual Studio с компонентом «Desktop development with C++» (ищется через
     `vswhere`) — генератор CMake по умолчанию; иначе Ninja + `g++` или `clang++` в `PATH`
     (MinGW-w64, LLVM) — генератор `Ninja`;
   - Linux: системный `c++`.

   Если чего-то нет, сборка не начинается, а в логе — что установить.

2. **Configure** — при каждой сборке (быстро, если ничего не изменилось):

   ```
   cmake -S <проект> -B <проект>/build -DCMAKE_BUILD_TYPE=<конфигурация>
         -DFETCHCONTENT_SOURCE_DIR_AETHER=<репозиторий AetherIDE>
   ```

   Генератор (`-G`) передаётся только для нового каталога сборки. Фреймворк берётся из
   репозитория, из которого запущена IDE, поэтому сеть не нужна (см.
   [codegen.md](./codegen.md#сборка)).
3. **Build** — `cmake --build <проект>/build --config <конфигурация>`.
4. **Результат** — путь к собранному плагину (`build/VST3/<Name>.vst3`) в логе и кнопка
   **Open folder**, которая показывает бандл в проводнике.

CMake запускается без оболочки: пути с пробелами передаются как есть, а **Stop** завершает
сам процесс CMake.

## Ошибки

| Что в логе                                    | Что делать                                                                                                       |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `CMake was not found in PATH`                 | установить CMake 3.22+, добавить в `PATH`, перезапустить IDE                                                     |
| `No C++ toolchain found`                      | Visual Studio 2022 с C++ или MinGW-w64 + Ninja в `PATH`                                                          |
| `The build directory is too deep for Windows` | перенести проект в папку с более коротким путём ([vst3-sdk.md](../framework/vst3-sdk.md#длина-путей-на-windows)) |
| подсказка про загрузку фреймворка             | IDE не нашла локальный фреймворк — нужна сеть и тег из `GIT_TAG`                                                 |

Сменить генератор (например, после установки Visual Studio) — удалить `build/` проекта.
