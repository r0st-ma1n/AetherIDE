# Architecture Standards

Этот документ фиксирует границы между частями `PrototypeIDE`, чтобы проект не превращался в набор случайно связанных файлов.

## Карта модулей

- `ide/`
  - desktop-приложение на `Electron`
  - окно приложения, `preload`, renderer UI и интеграция с Monaco
- `ide/backend/`
  - нативный `C++` backend, который используется IDE
- `framework/core/`
  - базовый аудио-фреймворк и абстракции для плагинов
- `framework/core/examples/gain/`
  - пример использования framework API

## Границы ответственности

### `ide/main.js`

- Управление жизненным циклом приложения
- Создание окна
- Настройка интеграции `Electron`
- Координация доступа к filesystem и внешним операциям

Не должен содержать сложную UI-логику.

### `ide/preload.js`

- Узкий и явный bridge между `main` и renderer
- Экспорт только безопасных API для окна

Не должен становиться свалкой произвольных helper-функций.

### Renderer (`ide/index.html` и связанный JS)

- Отрисовка интерфейса
- Работа с Monaco, canvas и состоянием редактора
- Синхронизация visual editor <-> code editor

Не должен напрямую использовать Node API в обход `preload`.

### `framework/core`

- Абстракции аудио-обработки
- Параметры, контекст обработки, контракт плагина
- Код, который можно переиспользовать вне текущего IDE UI

Не должен зависеть от `Electron` или UI-слоя.

### `ide/backend`

- Нативная логика, которая нужна самой IDE
- Интеграция между IDE и C++ подсистемой

Не должен дублировать framework-логику, если она может жить в `framework/core`.

## Правила роста архитектуры

- Повторившуюся логику переносить в общий модуль только после второго-третьего реального кейса.
- Если новая фича касается только редактора, не тянуть ее во `framework`.
- Если новая фича формирует публичную модель аудио-плагина, сначала рассматривать `framework/core`.
- Пример в `examples/gain` должен оставаться рабочим и читабельным образцом использования API.

## Изменения структуры

- Любое новое верхнеуровневое дерево директорий в репозитории нужно отдельно обосновать.
- Generated-файлы, временные сборочные артефакты и кэш не должны храниться рядом с исходниками.
