# Testing Standards

Этот проект пока выглядит как прототип, поэтому стандарт тестирования должен быть легким, но обязательным.

## Что проверять обязательно

- Изменения в `ide/`:
  - запуск приложения
  - сценарий, который затронул изменение
  - отсутствие явных ошибок в консоли для основного happy path
- Изменения в `framework/` или `ide/backend/`:
  - успешная сборка
  - ручная проверка затронутого поведения
  - если меняется core API, проверка `examples/gain`

## Минимум для PR

В каждом PR должна быть секция проверки:

```text
How to verify
1. ...
2. ...
3. ...
```

Если автоматических тестов нет, ручная проверка все равно обязательна.

## Приоритет для будущих автотестов

- Smoke test на запуск `Electron` IDE
- Проверки синхронизации visual editor <-> code editor
- Unit-тесты для core сущностей во `framework/core`
- Тесты на генерацию или преобразование кода, если эта логика будет расти

## Правила тестового кода

- Тест должен описывать наблюдаемое поведение, а не внутреннюю реализацию.
- Один тест проверяет один основной сценарий.
- Имена тестов должны быть понятны без чтения тела.
- Нельзя добавлять хрупкие проверки, которые ломаются от косметических изменений UI без изменения поведения.

## Когда тест обязателен

- При исправлении воспроизводимого бага
- При изменении framework API
- При добавлении логики преобразования данных или генерации кода

Если тест пока не добавляется, это должно быть осознанно отмечено в PR с причиной.
